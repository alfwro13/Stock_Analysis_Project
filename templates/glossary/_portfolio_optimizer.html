What the Portfolio Optimizer Does

The Portfolio Optimizer computes two textbook "optimal" allocations for a chosen account scope — Min-Variance and Max-Sharpe — using closed-form matrix algebra rather than a numerical optimization library. It shows the suggested weight for each candidate ticker next to its current weight, so you can compare your actual allocation against the two targets.

It's informational only: this app has no order execution, so nothing is rebalanced automatically. Held tickers are pre-selected candidates; Watchlist tickers can be opted in to see them suggested as a brand-new position with a nonzero weight.

Min-Variance Portfolio

The set of weights that would have produced the lowest historical volatility for the selected candidate tickers, derived directly from their covariance matrix.

w ∝ Σ⁻¹ · 1, normalized so the weights sum to 1 (Σ = annualised covariance matrix).

This is a closed-form solution — no iterative solver, no shorting or position-size constraints. It answers "if I only cared about the smoothest possible ride, how would I have weighted these holdings?"

Max-Sharpe Portfolio

The set of weights that would have maximized historical return per unit of risk — the tangency portfolio where a line from the risk-free rate is tangent to the efficient frontier.

w ∝ Σ⁻¹ · (μ − rf), normalized so the weights sum to 1 (μ = annualised expected returns, rf = the app's configured risk-free rate).

Like Min-Variance, this is closed-form and unconstrained. If a candidate's expected return sits below the risk-free rate, or the spread of expected returns across candidates is too thin, the Optimizer surfaces a warning instead of a misleading number.

Efficient Frontier

The curve of every portfolio that offers the lowest possible risk for a given expected return. The Optimizer traces it using two-fund separation: every point on the frontier is a linear combination of the Min-Variance and Max-Sharpe portfolios, so sweeping a blend factor between (and slightly beyond) the two traces the whole curve without a second optimization pass.

Negative (Short) Weights

Because the Optimizer is unconstrained — no "no shorting" rule, no per-position cap — a suggested weight can come out negative. This reflects the true closed-form math, not a recommendation to short a position: this app has no order execution and cannot act on it. Negative weights are always shown as-is, flagged with a badge, and never silently clipped to zero, since clipping would misrepresent the actual result.
