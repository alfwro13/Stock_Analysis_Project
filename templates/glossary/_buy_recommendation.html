What Buy Recommendation Combines

The Buy Recommendation tag is the last stage of the Buy-Signal Confluence Pipeline: a ticker is only labeled a Buy Recommendation when it has a bullish Signal Pillar Confluence (at least two of the Technical, Statistical, and ML pillars agree on "up," with none disagreeing) and that setup clears the Recommendation Risk/Reward Gate below. Regime-Weighted Conviction Score is carried alongside as context — it's documented elsewhere as deliberately never a competing Buy/Sell verdict, so it isn't part of this gate either; Pillar Confluence's own bullish/bearish call is the only directional trigger.

The Recommendation Risk/Reward Gate

A bullish setup with a poor reward-to-risk trade-off isn't worth flagging even if the signals agree. The gate computes Entry (current price), Stop (the same ATR-based stop-loss this app's Position Sizing tool already uses), and Take-Profit (see below), then requires (Take-Profit − Entry) / (Entry − Stop) >= Min. Risk/Reward Ratio — a configurable minimum (default 1.5) editable in Settings → Position Sizing Defaults. A ticker with bullish confluence but a Risk/Reward ratio below the minimum shows as "No" with the computed ratio, not a silent omission — the operator can see exactly why it didn't qualify.

Gate: bullish Pillar Confluence AND Risk/Reward >= Min. Risk/Reward Ratio. See position_sizing.passes_risk_reward_gate() and score_analysis.evaluate_buy_recommendation().
Take-Profit Target Resolution

The take-profit target prefers a real, already-computed price objective over a generic one: if the ticker has a CONFIRMED Pattern Detection result whose own family resolves to an "up" direction, its measured-move target is used (the highest one, if more than one bullish pattern is simultaneously confirmed). Otherwise the ML Quantile Regression Q90 band — the same upper-band prediction already shown on the Position Targets panel — stands in. If neither is available, the gate has no signal at all (shown as "No signal," never a fabricated number).

Why Not Kelly Criterion

This gate deliberately reuses the app's existing fixed-fractional, ATR-based stop-loss math rather than a Kelly Criterion calculation. This app already chose fixed-fractional sizing over Kelly for Position Sizing — Kelly's theoretically "optimal" bet size is aggressive enough that it assumes your edge estimate is exactly correct, which real-world edge estimates rarely are. The Recommendation Risk/Reward Gate reuses that same rationale rather than reopening it.
